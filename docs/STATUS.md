## Как устроен деплой

- `git push` в `main` → Cloudflare Workers Builds: `npm ci` → `npm run build` → `npx wrangler deploy` (≈1 минута).
  Токен сборки — «milav build token». Preview-сборки выключены.
- Переменные (не секреты) — в `wrangler.jsonc` → `vars`; при деплое они перезаписывают значения в панели.
- После каждого деплоя задача cron (раз в минуту) сама настраивает бота: вебхук с секретом, команды, кнопку меню «Каталог»,
  описание. Отметка — строка `settings.bot_setup` в D1 (`<id версии>|<SITE_URL>|<id бота>`).
- Миграции D1 в production применяются вручную (Cloudflare → D1 → catalog-prod → Console, или коннектор Cloudflare,
  или `wrangler d1 migrations apply catalog-prod --remote` с API-токеном). После ручного применения добавьте имя файла
  в таблицу `d1_migrations`, чтобы wrangler не применил его повторно.

## Ограничения среды ИИ-ассистента (важно для новой сессии)

- Из облачной среды Claude **нет сетевого доступа** к `api.telegram.org`, `api.cloudflare.com` и `*.workers.dev`:
  `wrangler deploy`/`wrangler secret` оттуда не работают. Деплой — только через `git push`.
- Коннектор Cloudflare умеет: D1 (создать, SQL-запросы), KV/R2 (создать), список Workers. Не умеет: загружать код, задавать секреты, писать в KV.
  Большие SQL-пакеты (≈25 КБ+) коннектор отклоняет с ошибкой 403 — выполнять по 1–2 лота за запрос.
- Сайт и панель Cloudflare можно открывать во встроенном браузере (при связке с компьютером владельца).
- Секреты и пароли вводит владелец сам.

## Что осталось (по приоритету)

0. **Опрос при первом запуске**: посмотреть в Telegram (админка → «Статистика» → «Пройти опрос самому») и включить
   там же переключателем. Тексты вопросов — `src/onboarding/Survey.tsx`, варианты ответов — `src/lib/match.ts`.
1. **Заявка №1 не дошла в группу.** После деплоя: админка → «Заявки» → «Проверить» покажет точную причину.
   Обычно бот не добавлен в группу: добавьте @bismarketbot в группу менеджеров (ID группы бот запомнит сам, если добавляет
   администратор) или напишите в группе `/setgroup` → «Отправить недоставленные».
2. **Оплата размещения** сейчас вне приложения (заявка в группу). Цены: размещение ₪ 199, оценка ₪ 1 500, аудит ₪ 4 000 —
   меняются в админке («Объявления» → «От продавцов»), там же режим «публиковать сразу / после проверки».
   PayPal при необходимости — `docs/PAYMENTS.md`.
3. **Проверить в Telegram вживую**: заявка → группа → «Взять в работу»; продавец: черновик → отправка → оплата → публикация →
   запрос на изменение.
4. **@BotFather → `/newapp`**: бот @bismarketbot, короткое имя `app`, URL `https://bmarket.moshemadwords.workers.dev/`,
   обложка 640×360. Нужно для прямых ссылок `t.me/bismarketbot/app?startapp=lot-1001` (и кнопки «Открыть в админке» в группе).
5. **Перевыпустить токен бота** (`/revoke` в @BotFather) — он был в чате; затем обновить секрет `TELEGRAM_BOT_TOKEN`
   в панели. Вебхук перенастроится сам в течение минуты.
6. **Демо-объявления** перед реальным запуском снять с публикации (в админке «Снять») — они помечены
   в скрытых заметках «ДЕМО». Удалить совсем можно SQL-запросом (см. `seed/demo-lots.sql`, первые строки).
7. Название бренда (сейчас `PROJECT_NAME = BMarket`), домен → Custom Domain в Cloudflare, затем обновить `SITE_URL`
   и адрес вебхука PayPal.
8. Turnstile (ключи `TURNSTILE_SITE_KEY` / секрет `TURNSTILE_SECRET_KEY`) — после домена.
9. Cloudflare Web Analytics (`CF_ANALYTICS_TOKEN`), Google Search Console + sitemap.
10. Резервные копии: в GitHub → Settings → Secrets → Actions добавить `CLOUDFLARE_API_TOKEN` (права D1 Edit)
    и `CLOUDFLARE_ACCOUNT_ID`; проверить workflow «Резервная копия D1».
11. Текст `/privacy` согласовать с израильским юристом (добавить: данные продавцов, оплата через PayPal,
    ответы опроса; проверить допустимость заранее отмеченного согласия в форме заявки).
12. Лимит KV Free — 1000 записей в день (≈500 фото): если продавцов станет много — включить R2 (нужна карта)
    и добавить привязку `PHOTOS` — фото пойдут в R2 без изменения кода.
