# ТЗ: Telegram Mini App — каталог бизнесов на продажу

Oct 24, 2026 · @Моше Шанин

## 1. Общие сведения

Нужно создать каталог израильских бизнесов на продажу, который работает как мини-приложение Telegram и как обычный сайт по своему домену. Контент ведут 2 администратора прямо в мини-приложении; посетители только смотрят объявления и оставляют заявки.

**Цель.** Привлекать частных покупателей и получать от них заявки на конкретные бизнесы. Каждая заявка мгновенно приходит менеджерам в Telegram и сохраняется в админ-панели.

**Аудитория.** Частные покупатели, русскоязычные, преимущественно в Израиле. Пользователи заходят из Telegram (мини-приложение) или из поиска Google (веб-версия).

**Объём.** На старте 10 объявлений, затем примерно +5 в месяц, то есть около 70 через год. Это маленький объём: бесплатных тарифов сервисов хватит с запасом, но архитектура не должна мешать росту до нескольких сотен объявлений.

### Принятые решения

| Вопрос | Решение |
| --- | --- |
| Язык интерфейса | Только русский |
| Регион | Израиль, навигация по городам |
| Валюта | Цены вводятся в шекелях (₪), рядом показываются USD и EUR по текущему курсу |
| Конфиденциальность | Реальное название и точный адрес бизнеса скрыты от посетителей |
| Статусы объявлений для посетителей | Не показываются; проданный бизнес админ просто снимает с публикации |
| Фильтры и поиск | Не нужны; единственная навигация — разбивка по городам |
| Избранное, сравнение | Не нужны |
| Уведомления о новых бизнесах | Нужны, через Telegram-бота |
| Регистрация посетителей | Не нужна, каталог открытый |
| Связь с продавцом | Форма заявки; менеджеры получают её в Telegram |
| Админ-панель | Внутри мини-приложения, вход через Telegram, 2 администратора |
| SEO и аналитика | Нужны |
| Домен, бот, фирменный стиль | Пока нет, создаются в рамках проекта |
| Разработка | Владелец проекта сам, с помощью ИИ-ассистента |
| Стоимость | Только бесплатные тарифы; платится лишь домен (около 10 USD в год) |

### Термины

- **Мини-приложение (Mini App)** — веб-страница, которая открывается внутри Telegram по кнопке бота.
- **Объявление (лот)** — карточка одного бизнеса на продажу.
- **Заявка (лид)** — запрос посетителя на подробности по конкретному лоту.
- **Подписчик** — пользователь Telegram, который разрешил боту присылать уведомления о новых лотах.
- **initData** — подписанные Telegram данные о пользователе, которые мини-приложение получает при открытии; по ним сервер проверяет, кто зашёл.

## 2. Технологический стек и инфраструктура

Весь проект работает на бесплатных тарифах: код хранится в GitHub, а сайт, мини-приложение, бот, база данных и фото размещаются в Cloudflare. Единственный обязательный расход — домен, около 10 USD в год; на старте можно обойтись и без него, на бесплатном адресе `*.workers.dev`.

Все пользователи обращаются к одному приложению на Cloudflare Workers; оно напрямую работает с базой D1 и хранилищем фото R2, обменивается сообщениями с Telegram и раз в день забирает курсы у Банка Израиля. Домен обслуживает Cloudflare DNS.

| Компонент | Технология | Зачем |
| --- | --- | --- |
| Репозиторий | GitHub, приватный | Хранение кода; каждый push в `main` автоматически собирается и выкатывается через Cloudflare Workers Builds |
| Хостинг | Cloudflare Workers, тариф **Free** | Страницы, API, вебхук бота, задачи по расписанию (Cron Triggers) |
| Фреймворк | Astro с серверным рендерингом + TypeScript | Лёгкий код, который укладывается в лимиты бесплатного Workers; готовый HTML для SEO |
| Интерактивные части | React-компоненты внутри Astro | Админ-панель, форма заявки, галерея |
| Стили | Tailwind CSS + цвета темы Telegram | Быстрая вёрстка, светлая и тёмная тема |
| База данных | Cloudflare D1 (SQLite) + Drizzle ORM | Объявления, заявки, подписчики, курсы, события; подключается напрямую из Worker |
| Фото | Cloudflare R2 + поддомен `img.<домен>` | Хранение и раздача изображений |
| Домен и DNS | Cloudflare DNS | Управление доменом |
| Защита формы | Cloudflare Turnstile | Проверка «не робот» в веб-версии |
| Аналитика трафика | Cloudflare Web Analytics | Посещаемость без cookie |
| Бот | Telegram Bot API, библиотека grammY | Запуск мини-приложения, заявки менеджерам, рассылки |
| SDK мини-приложения | `telegram-web-app.js` или `@telegram-apps/sdk-react` | Тема, кнопки, initData, запрос разрешения на сообщения |

### Почему так, а не иначе

- **Vercel убран.** Его бесплатный тариф Hobby [разрешён только для некоммерческого личного использования](https://vercel.com/docs/limits/fair-use-guidelines), а каталог бизнесов на продажу — коммерческий проект. У бесплатного тарифа Cloudflare Workers такого запрета нет.
- **Astro вместо Next.js.** На бесплатном Workers размер приложения ограничен [3 МБ в сжатом виде, а процессорное время — 10 мс на запрос](https://developers.cloudflare.com/workers/platform/limits). Next.js через адаптер OpenNext [часто не помещается в 3 МБ](https://opennext.js.org/cloudflare/troubleshooting); Astro даёт в разы меньший и более быстрый код.
- **D1 теперь подходит.** Раньше мешало то, что код на Vercel достаёт до D1 только через медленный REST API. Теперь код работает внутри Cloudflare и обращается к базе напрямую.
- **Фото сжимаются в браузере.** Перед загрузкой админ-панель уменьшает фото и делает 2 размера: 1600 px и 600 px для списков. Это экономит процессорное время Worker и не требует платного сервиса обработки изображений.

### Бесплатные лимиты и нагрузка проекта

| Ресурс | Бесплатный лимит | Что это значит для проекта |
| --- | --- | --- |
| Запросы к Worker | 100 000 в день | При 70 лотах ожидается 1–5 тыс. в день; запас в 20 раз и больше |
| Статические файлы (JS, CSS, шрифты) | Без ограничений | Не расходуют лимит запросов |
| Процессорное время | 10 мс на запрос | Публичные страницы кешируются в Cloudflare; обработка фото — в браузере |
| Размер приложения | 3 МБ в сжатом виде | Проверять при каждой сборке; не подключать тяжёлые библиотеки |
| Внешние запросы из одного вызова | 50 | Рассылка подписчикам идёт порциями (раздел 7) |
| Задачи по расписанию (Cron Triggers) | 5 на аккаунт | Используются 2 |
| D1: чтение и запись | 5 млн строк чтения и 100 000 строк записи в день | Нужны индексы по полям, по которым идёт выборка |
| D1: объём | 500 МБ на базу, 5 ГБ на аккаунт | Тексты сотен лотов и тысячи заявок занимают единицы МБ |
| D1: восстановление (Time Travel) | 7 дней | Плюс еженедельная выгрузка (раздел 12) |
| R2 | 10 ГБ, 1 млн операций записи и 10 млн чтения в месяц, трафик бесплатный | Тысячи сжатых фото |

Лимиты D1 и Workers сбрасываются ежедневно в 00:00 UTC; при превышении запросы возвращают ошибки до сброса. Если проект вырастет, переход на платный Workers Paid стоит 5 USD в месяц и снимает эти ограничения без изменения кода. В панели Cloudflare нужно включить уведомление о приближении к лимитам.

### Окружения, привязки и секреты

- **Production** — ветка `main`, основной домен, база `catalog-prod`.
- **Staging** — отдельный Worker на адресе `*.workers.dev` с базой `catalog-staging` и тестовым ботом, чтобы не слать тестовые сообщения в рабочий чат менеджеров.
- Секреты хранятся только в настройках Worker (через панель Cloudflare или `wrangler secret put`), никогда в коде.

| Имя | Тип | Содержимое |
| --- | --- | --- |
| `DB` | Привязка D1 | База данных |
| `PHOTOS` | Привязка R2 | Бакет с фото |
| `TELEGRAM_BOT_TOKEN` | Секрет | Токен бота |
| `TELEGRAM_WEBHOOK_SECRET` | Секрет | Проверка вебхука |
| `TURNSTILE_SECRET_KEY` | Секрет | Проверка формы в веб-версии |
| `ADMIN_TELEGRAM_IDS` | Переменная | Telegram ID двух администраторов через запятую |
| `MANAGERS_CHAT_ID` | Переменная | ID группы менеджеров |

## 3. Роли и права доступа

В системе две роли: посетитель без регистрации и администратор, которого сервер узнаёт по Telegram ID из подписанных данных initData.

| Действие | Посетитель | Администратор |
| --- | --- | --- |
| Смотреть каталог и карточки | Да | Да |
| Видеть скрытые поля (реальное название, адрес, контакты владельца) | Нет | Да |
| Отправить заявку | Да | Да |
| Подписаться на уведомления о новых бизнесах | Да, только в Telegram | Да |
| Создавать, редактировать, публиковать и снимать объявления | Нет | Да |
| Видеть и обрабатывать заявки | Нет | Да |
| Управлять справочниками городов и отраслей | Нет | Да |
| Смотреть статистику | Нет | Да |

### Как работает вход администратора

1. Администратор открывает мини-приложение через бота. Telegram передаёт приложению строку `initData` с данными пользователя и подписью.
2. Приложение отправляет эту строку на сервер с каждым запросом к админ-API (заголовок `Authorization: tma <initData>`).
3. Сервер проверяет подпись HMAC-SHA256 по токену бота [по алгоритму из документации Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app) и отклоняет данные старше 24 часов.
4. Если подпись верна и `user.id` есть в списке `ADMIN_TELEGRAM_IDS`, запрос выполняется. Иначе — ответ 403.
5. Для администратора в интерфейсе появляется кнопка «Админ-панель». Посетители её не видят, но защита держится на проверке на сервере, а не на скрытии кнопки.

Оба администратора имеют одинаковые права. Разделение ролей не требуется. Добавить или заменить администратора можно, изменив переменную `ADMIN_TELEGRAM_IDS` в настройках Worker в Cloudflare.

Админ-панель доступна только внутри Telegram. В веб-версии в браузере её нет, поэтому отдельная авторизация на сайте не нужна.

## 5. Публичная часть: экраны и функции

Посетитель видит 6 экранов: главную, страницу города, карточку бизнеса, форму заявки, подтверждение и служебные страницы. В Telegram и в браузере это одни и те же страницы, различаются только элементы управления.

| Экран | Адрес | Что на нём |
| --- | --- | --- |
| Главная | `/` | Заголовок, лента городов, список всех объявлений, блок подписки |
| Город | `/city/<slug>` | Список объявлений одного города |
| Карточка | `/business/<lot>-<slug>` | Полная информация о бизнесе и кнопка заявки |
| Форма заявки | `/business/<lot>-<slug>/request` | Поля заявки (в Telegram может быть всплывающим окном) |
| Заявка отправлена | — | Подтверждение и возврат в каталог |
| О сервисе, политика конфиденциальности | `/about`, `/privacy` | Тексты от владельца проекта |

### 5.1. Главная

- **Лента городов** — горизонтально прокручиваемые кнопки: «Все города», затем города, где есть опубликованные объявления, с числом объявлений: «Хайфа · 3». Города без объявлений не показываются. Это единственная навигация; фильтров и поиска нет.
- **Список объявлений** — сначала закреплённые (`is_featured`), затем по дате публикации, новые сверху. При 10–70 объявлениях пагинация не нужна; при росте свыше 50 — подгрузка по 20 при прокрутке.
- **Карточка в списке**: обложка (соотношение 4:3), название, город и отрасль, цена в шекелях крупно, под ней примерная цена в USD, прибыль в месяц и окупаемость, если указаны. Метка «Новое» для объявлений младше 7 дней.
- **Блок подписки** (только в Telegram): «Получать уведомления о новых бизнесах» с кнопкой. Если пользователь уже подписан — «Вы подписаны» и ссылка «Отписаться».
- **Пустое состояние**: если объявлений нет — текст «Скоро здесь появятся новые предложения» и кнопка подписки.

### 5.2. Страница города

Тот же список, но только по выбранному городу; в ленте городов он подсвечен. Заголовок «Бизнесы на продажу в Хайфе». У каждой страницы города свой адрес, заголовок и описание для поисковиков (раздел 10).

### 5.3. Карточка бизнеса

Порядок блоков сверху вниз:

1. **Галерея фото** — листание свайпом, счётчик «3 / 12», открытие на весь экран по нажатию.
2. **Лот №, название, город и район, отрасль.**
3. **Цена**: «₪ 450 000», ниже мелко «≈ $121 000 · ≈ €112 000», метка «Торг возможен». Подсказка по нажатию: «Курс Банка Израиля на 23.10.2026».
4. **Ключевые показатели** плитками 2×2: оборот в месяц, чистая прибыль в месяц, окупаемость, аренда в месяц. Пустые показатели не выводятся.
5. **Описание** с форматированием.
6. **Что входит в продажу** — список с галочками.
7. **Характеристики** — таблица: год открытия, сотрудники, площадь, аренда до, форма собственности, лицензия, передача дел.
8. **Причина продажи.**
9. **Видео**, если есть.
10. **Пояснение о конфиденциальности**: «Название и точный адрес сообщаются после заявки».
11. **Кнопка «Узнать подробнее»** — открывает форму заявки.
12. **Кнопка «Поделиться»** — копирует ссылку; в Telegram открывает выбор чата.

### 5.4. Форма заявки

| Поле | Обязательно | Правила |
| --- | --- | --- |
| Имя | Да | 2–60 символов; в Telegram заполняется из профиля, можно изменить |
| Телефон | Да | Израильский формат (05X-XXX-XXXX) или международный с «+» |
| Как связаться | Да | Телефон, WhatsApp, Telegram; по умолчанию Telegram в мини-приложении и телефон на сайте |
| Комментарий | Нет | До 500 символов |
| Согласие с политикой конфиденциальности | Да | Галочка со ссылкой на `/privacy` |

В Telegram можно предложить кнопку «Поделиться номером» (метод `requestContact`), чтобы не вводить телефон вручную. Защита от спама описана в разделе 12.

После отправки — экран «Спасибо! Менеджер свяжется с вами в течение рабочего дня» и кнопка «Вернуться в каталог». В Telegram, если пользователь ещё не подписан, там же предлагается подписка.

### 5.5. Особенности внутри Telegram

- При открытии вызываются `ready()` и `expand()`; цвета берутся из темы пользователя (`themeParams`), тёмная тема работает автоматически.
- На внутренних экранах используется системная кнопка «Назад» Telegram (`BackButton`), а не своя.
- Кнопка «Узнать подробнее» и «Отправить заявку» — системная нижняя кнопка Telegram (`MainButton`).
- Прямые ссылки на объявление: `https://t.me/<бот>/<приложение>?startapp=lot-1001` — мини-приложение сразу открывает нужную карточку (параметр `start_param`).
- Лёгкая вибрация (`HapticFeedback`) при отправке заявки.

### 5.6. Особенности в браузере

- Собственная шапка с логотипом-текстом и ссылкой «Открыть в Telegram».
- Кнопка «Узнать подробнее» закреплена внизу экрана на телефоне и справа от описания на компьютере.
- Подписка на уведомления в браузере недоступна; вместо неё кнопка «Подписаться в Telegram», ведущая в бота.

## 6. Заявки и уведомления менеджерам

Каждая заявка сначала сохраняется в базе, затем бот присылает её в закрытую группу менеджеров с кнопками; если Telegram недоступен, заявка всё равно не теряется и видна в админ-панели.

### 6.1. Порядок обработки

1. Посетитель отправляет форму. Сервер проверяет поля, согласие и защиту от спама.
2. Заявка записывается в таблицу `leads` со статусом «Новая».
3. Бот отправляет сообщение в группу менеджеров (`MANAGERS_CHAT_ID`), в которой состоят оба администратора.
4. Если отправка не удалась, сервер повторяет её до 3 раз с паузой; при неудаче заявка помечается флагом «не доставлена в Telegram», и админ-панель показывает её вверху списка.
5. Посетитель видит экран подтверждения.

### 6.2. Сообщение в группе менеджеров

```
🆕 Новая заявка №57
Лот №1001 — Кофейня с террасой в центре Хайфы
Цена: ₪ 450 000

Имя: Дмитрий
Телефон: +972 54 123 4567
Связаться: WhatsApp
Telegram: @dmitry_k
Комментарий: Интересует оборот за последний год

Источник: мини-приложение · 24.10.2026 11:42
```

Кнопки под сообщением:

- **«Взять в работу»** — ставит статус «В работе», записывает, кто взял; сообщение редактируется: «В работе у @admin1». Второй администратор видит, что заявка занята.
- **«Открыть в админке»** — открывает мини-приложение сразу на этой заявке.
- Телефон в сообщении кликабельный; для WhatsApp добавляется ссылка `https://wa.me/972541234567`.

Скрытые поля лота (реальное название, адрес, контакты продавца) в группу **не отправляются** — менеджер смотрит их в админ-панели. Так данные не расходятся по перепискам.

### 6.3. Учёт заявок в админ-панели

Описан в разделе 8.3: список, статусы, заметки, фильтр по статусу и лоту, выгрузка в CSV.

## 7. Уведомления подписчикам о новых бизнесах

При публикации нового лота бот один раз присылает подписчикам сообщение с фото, ценой и кнопкой открытия карточки. Подписка — на все новые объявления, без выбора городов.

### 7.1. Как подписаться и отписаться

- **В мини-приложении**: кнопка «Получать уведомления» вызывает `requestWriteAccess()` — Telegram показывает системный запрос разрешить боту писать. При согласии сервер сохраняет подписчика.
- **В боте**: команда `/start` показывает приветствие и две кнопки: «Открыть каталог» и «Подписаться на новые бизнесы».
- **Отписка**: команда `/stop`, кнопка «Отписаться» под каждой рассылкой и ссылка в блоке подписки в мини-приложении.
- Если пользователь заблокировал бота, Telegram вернёт ошибку 403 — подписчик автоматически помечается неактивным.

### 7.2. Команды бота

| Команда | Действие |
| --- | --- |
| `/start` | Приветствие, кнопки «Открыть каталог» и «Подписаться» |
| `/start lot-1001` | Сразу кнопка на конкретный лот (для ссылок из рекламы) |
| `/subscribe` | Подписаться |
| `/stop` | Отписаться |
| `/help` | Как пользоваться каталогом и связаться с менеджером |

Кнопка меню бота (Menu Button) настраивается на открытие мини-приложения.

### 7.3. Когда и что отправляется

1. Администратор публикует лот, у которого раньше не было публикации. В форме есть переключатель «Уведомить подписчиков», включённый по умолчанию.
2. Сервер создаёт задачу рассылки и ставит лоту отметку `notified_at`, чтобы повторная публикация после снятия не рассылалась снова.
3. Рассылка идёт порциями: задача по расписанию раз в минуту отправляет до 40 сообщений, потому что на бесплатном Workers один вызов может сделать не более 50 внешних запросов. 300 подписчиков получают уведомление примерно за 8 минут.
4. По окончании администраторы получают в группе итог: «Рассылка по лоту №1001: доставлено 312, заблокировали бота 4».

Шаблон сообщения: фото-обложка, подпись «Новый бизнес на продажу: Кофейня с террасой в центре Хайфы · ₪ 450 000 · прибыль ₪ 35 000 в месяц», кнопки «Смотреть» (открывает мини-приложение на этой карточке) и «Отписаться».

Не более 1 рассылки в 2 часа: если за это время опубликовано несколько лотов, они уходят одним сообщением-подборкой. Это защищает подписчиков от потока сообщений при массовом наполнении каталога.

## 8. Админ-панель внутри мини-приложения

Админ-панель — раздел того же мини-приложения по адресу `/admin`, рассчитанный на работу с телефона; в нём 5 вкладок: объявления, заявки, справочники, подписчики, статистика.

### 8.1. Объявления

- Список всех лотов с обложкой, номером, названием, городом, статусом (черновик, опубликован, скрыт), числом просмотров и заявок за 30 дней.
- Переключатель статусов вверху: «Все / Опубликованные / Черновики / Скрытые».
- Кнопка «+ Новое объявление».
- Действия с лотом: редактировать, опубликовать, скрыть, дублировать (для похожих объектов), открыть как посетитель, удалить (только черновики; опубликованные и скрытые не удаляются, чтобы не потерять историю заявок).

### 8.2. Форма объявления

- Поля сгруппированы в 5 блоков: «Основное», «Цифры», «Описание», «Фото и видео», «Скрытые данные». Блок «Скрытые данные» выделен цветом и подписан «Не видно посетителям».
- Числовые поля форматируются при вводе: «450 000».
- Окупаемость считается автоматически и показывается рядом с полем прибыли.
- Описание — простой редактор Markdown с кнопками: жирный, список, заголовок; рядом предпросмотр.
- **Фото**: выбор нескольких файлов из галереи телефона; перед загрузкой каждое фото сжимается в браузере до 1600 px по длинной стороне в формате WebP, плюс копия 600 px для списков; загрузка в R2 через админ-API; индикатор прогресса; порядок меняется перетаскиванием; первое — обложка; у каждого фото кнопка удаления.
- Автосохранение черновика каждые 10 секунд, чтобы не потерять ввод, если Telegram закроет приложение.
- Перед публикацией проверка обязательных полей: название, город, отрасль, цена, краткое и полное описание, минимум 1 фото.
- Кнопка «Предпросмотр» показывает карточку так, как её увидит посетитель.
- При публикации — переключатель «Уведомить подписчиков» (раздел 7).

### 8.3. Заявки

- Список заявок, новые сверху, с непрочитанными выделенными; счётчик новых на вкладке.
- Фильтры: по статусу и по лоту.
- Карточка заявки: все поля заявки, ссылка на лот, скрытые данные лота (название, адрес, контакты продавца), кнопки «Позвонить», «Написать в WhatsApp», «Написать в Telegram».
- Смена статуса: новая → в работе → закрыта: сделка / закрыта: отказ. Поле заметки.
- Статус, изменённый кнопкой в группе Telegram, сразу отражается здесь, и наоборот.
- Выгрузка заявок в CSV за выбранный период.

### 8.4. Справочники

Добавление, переименование и сортировка городов и отраслей. Удаление разрешено, только если к записи не привязаны лоты.

### 8.5. Подписчики

Число активных подписчиков, прирост за 7 и 30 дней, история рассылок с итогами доставки. Список подписчиков с именами не нужен.

### 8.6. Статистика

Описана в разделе 11.

### 8.7. Журнал изменений

У каждого лота хранится, кто и когда создал, изменил, опубликовал или скрыл его. Это нужно, чтобы два администратора не путались в правках друг друга. Если оба одновременно редактируют один лот, при сохранении второй получает предупреждение «Объявление изменено другим администратором» и может обновить форму.

## 9. Валюты: шекели, доллары, евро

Цены вводятся и хранятся только в шекелях; суммы в USD и EUR рассчитываются по официальному представительскому курсу Банка Израиля, который сервер загружает раз в день.

- **Источник** — представительский курс Банка Израиля (שער יציג). Банк публикует его [ежедневно](https://boi.org.il/en/economic-roles/statistics/foreign-exchange-market/exchange-rates/) по рабочим дням; ключ API не нужен. Курс можно получать через [базу рядов банка (SDMX)](https://www.boi.org.il/media/upqgqpuv/extracting-representative-exchange-rates-from-the-new-series-database.pdf), ряды `RER_USD_ILS` и `RER_EUR_ILS`, или через публичный JSON-адрес банка. Конкретный адрес нужно проверить на этапе разработки: банк уже менял пути API.
- **Загрузка** — ежедневная задача Cloudflare Cron Trigger в 14:00 UTC (после публикации курса). Результат сохраняется в таблицу `exchange_rates`.
- **Сбой источника** — используется последний сохранённый курс. Если он старше 7 дней, суммы в USD и EUR скрываются, и администраторам приходит сообщение в группу.
- **Округление** — до тысячи для сумм от 10 000, со знаком «≈»: «≈ $121 000». Валютные суммы носят справочный характер.
- **Пояснение** — в карточке по нажатию: «Пересчёт по курсу Банка Израиля на 23.10.2026. Окончательная цена — в шекелях».
- **Где показываются** — цена в списке (только USD), цена в карточке (USD и EUR). Оборот, прибыль и аренда показываются только в шекелях, чтобы не перегружать экран.

## 10. Веб-версия и SEO

Все публичные страницы отдаются сервером уже готовым HTML, чтобы Google видел объявления; у каждого лота и города свой адрес, заголовок, описание и превью для соцсетей.

### 10.1. Обязательные требования

- **Рендеринг**: страницы списка, города и карточки — серверные (Astro SSR) и кешируются в Cloudflare на 10 минут. При публикации или изменении лота кеш нужных страниц сбрасывается сразу (`Cache API`), чтобы изменения появлялись без задержки.
- **Заголовок страницы (`title`)**:
  - карточка: «Кофейня с террасой в центре Хайфы — ₪ 450 000 | <Название проекта>»;
  - город: «Бизнес на продажу в Хайфе — <число> предложений | <Название проекта>»;
  - главная: «Готовый бизнес на продажу в Израиле | <Название проекта>».
- **Описание (`meta description`)**: для карточки — `short_description`; для городов и главной — шаблонный текст.
- **Превью для соцсетей и мессенджеров (Open Graph)**: обложка лота, название, цена. Ссылка, отправленная в Telegram или WhatsApp, показывается с фото.
- **Разметка schema.org**: для карточки — `Product` с `Offer` (цена в ILS) и `BreadcrumbList` (Главная → Город → Лот); для главной — `Organization`.
- **Карта сайта** `/sitemap.xml` генерируется автоматически: главная, страницы городов с объявлениями, опубликованные лоты с датой изменения.
- **`/robots.txt`**: закрыть `/admin` и `/api`, указать адрес карты сайта.
- **Канонический адрес** (`canonical`) на каждой странице; при смене названия лота адрес меняется, а старый перенаправляет на новый (301), потому что в адресе есть номер лота.
- **Снятые лоты** (`hidden`): страница отвечает кодом 410 и показывает «Этот бизнес снят с продажи» со ссылками на другие лоты того же города. Из карты сайта такие лоты убираются.
- **Язык**: `<html lang="ru">`.
- **Фото**: через `img srcset`, ленивая загрузка, атрибут `alt` из подписи фото или названия лота.

### 10.2. После запуска

- Подключить домен в Google Search Console и отправить карту сайта.
- Страница `/about` с 2–3 абзацами о сервисе, процессе покупки и контактами — она помогает и поисковикам, и доверию посетителей.

**Открытый вопрос:** название проекта (бренд) пока не выбрано; оно нужно для домена, бота, заголовков страниц и логотипа.

## 11. Аналитика

Бизнес-метрики (просмотры лотов, заявки, конверсия) считаются собственными событиями в базе и показываются во вкладке «Статистика»; общий трафик сайта — через бесплатный Cloudflare Web Analytics.

### 11.1. Что показывает вкладка «Статистика»

Период выбирается: 7 дней, 30 дней, 90 дней, всё время.

| Показатель | Как считается |
| --- | --- |
| Открытия каталога | События `app_open`, отдельно мини-приложение и сайт |
| Просмотры карточек | События `listing_view` |
| Открытия формы заявки | События `lead_form_open` |
| Заявки | Записи в `leads` |
| Конверсия в заявку | Заявки / просмотры карточек, в процентах |
| Подписчики | Активные на конец периода и прирост |
| Топ-10 лотов | По просмотрам и по заявкам |
| Города | Просмотры и заявки по городам |
| Источники заявок | Мини-приложение, сайт, метки UTM |

График по дням: просмотры карточек и заявки на одной оси времени.

### 11.2. Правила сбора

- Событие `listing_view` записывается не чаще 1 раза в 30 минут от одного посетителя по одному лоту.
- `visitor_hash` — хеш от Telegram ID (в мини-приложении) или случайного идентификатора в браузере; имена, телефоны и IP в событиях не хранятся.
- Просмотры администраторов не учитываются.
- Метки UTM из ссылки сохраняются при первом заходе и прикрепляются к заявке — так видно, какая реклама приносит заявки.

## 12. Безопасность и персональные данные

Проект хранит телефоны и имена покупателей, а также контакты продавцов, поэтому каждый запрос к данным проверяется на сервере, а сбор данных сопровождается политикой конфиденциальности по израильскому закону.

### 12.1. Защита доступа

- Каждый запрос к `/api/admin/*` проверяет подпись `initData` и список администраторов (раздел 3).
- Вебхук бота принимает только запросы с правильным заголовком `X-Telegram-Bot-Api-Secret-Token`.
- Задачи по расписанию (курсы, рассылки) запускаются только внутри Cloudflare и не имеют внешнего адреса.
- Публичные запросы к базе выбирают поля по явному списку; скрытые поля не выбираются вообще. На это пишется автоматический тест: в ответе публичного API и HTML карточки не должно быть значений `real_name`, `exact_address`, `owner_*`, `internal_notes`.
- Загрузка фото — только администраторами, через админ-API; принимаются сжатые в браузере файлы WebP до 2 МБ.
- Все входные данные проверяются схемами (библиотека Zod); описание в Markdown выводится через санитайзер, чтобы в него нельзя было внедрить скрипт.

### 12.2. Защита формы заявки от спама

- Скрытое поле-ловушка (honeypot): если оно заполнено, заявка тихо отбрасывается.
- Не более 5 заявок в час с одного IP или Telegram ID.
- В веб-версии — проверка Cloudflare Turnstile (бесплатная, без картинок с выбором). В мини-приложении она не нужна: запрос подписан Telegram.

### 12.3. Персональные данные

- В Израиле с 14 августа 2025 года действует [поправка 13 к Закону о защите частной жизни](https://iapp.org/news/a/israel-marks-a-new-era-in-privacy-law-amendment-13-ushers-in-sweeping-reform), которая усилила требования к прозрачности и защите данных.
- Нужна страница `/privacy`: какие данные собираются (имя, телефон, Telegram), зачем (связь по заявке, уведомления), кто их видит, сколько хранятся, где хранятся, как запросить удаление.
- Галочка согласия в форме заявки обязательна; время согласия сохраняется.
- Срок хранения заявок — 24 месяца, затем имя и телефон автоматически удаляются, остаётся обезличенная статистика.
- База D1 создаётся с подсказкой региона «Западная Европа» (weur), ближайшего к Израилю. Данные хранятся за пределами Израиля — это нужно указать в политике.
- **Рекомендация:** текст политики конфиденциальности и условий использования согласовать с израильским юристом; ТЗ не заменяет юридическую консультацию.

### 12.4. Резервные копии

- Функция D1 Time Travel позволяет восстановить базу на любой момент за последние 7 дней (бесплатный тариф).
- Дополнительно: еженедельная выгрузка базы (через GitHub Actions) в отдельный закрытый бакет R2. Копии старше 8 недель удаляются автоматически.
- Фото в R2 при удалении лота не стираются сразу, а удаляются через 30 дней.

## 14. Подготовка аккаунтов и этапы разработки

Работу стоит вести в 9 этапов, каждый из которых заканчивается работающим результатом на настоящем домене; переходить к следующему этапу — только после прохождения проверки предыдущего.

### 14.1. Подготовка до начала разработки

- [ ] Выбрать название проекта (бренд).
- [ ] Купить домен. `.com` можно купить прямо в Cloudflare; если нужен `.co.il`, его покупают у аккредитованного израильского регистратора, а затем переносят управление DNS в Cloudflare.
- [ ] Создать аккаунт GitHub и приватный репозиторий.
- [ ] Создать бесплатный аккаунт Cloudflare и подключить к нему репозиторий GitHub через Workers Builds.
- [ ] Создать 2 базы D1, рабочую и тестовую, с регионом «Западная Европа».
- [ ] В Cloudflare: добавить домен; создать бакет R2 для фото (публичный доступ через поддомен `img.<домен>`) и закрытый бакет для резервных копий; выпустить API-токен Cloudflare для резервного копирования через GitHub Actions; создать ключ Turnstile.
- [ ] Привязать домен к Worker как пользовательский домен (Custom Domain); сертификат HTTPS выпускается автоматически.
- [ ] В @BotFather: создать рабочего и тестового бота, зарегистрировать мини-приложение командой `/newapp`, задать кнопку меню, описание и аватар.
- [ ] Создать закрытую группу менеджеров, добавить в неё обоих администраторов и бота, узнать ID группы.
- [ ] Узнать Telegram ID обоих администраторов.
- [ ] Подготовить тексты «О сервисе» и политики конфиденциальности.
- [ ] Подготовить материалы для первых 10 лотов: фото, цифры, описания, скрытые данные.

### 14.2. Этапы

1. **Каркас проекта.** Astro с адаптером Cloudflare, TypeScript, Tailwind, Drizzle, привязка D1, автодеплой на Workers из GitHub, домен.
   - Проверка: сайт открывается по домену по HTTPS; push в `main` автоматически обновляет сайт; push в ветку staging обновляет тестовый Worker; размер сборки в сжатом виде меньше 3 МБ.
2. **База данных.** Все таблицы раздела 4, миграции, начальные города и отрасли, 3 тестовых лота.
   - Проверка: миграции применяются одной командой; тест на отсутствие скрытых полей в публичных данных проходит.
3. **Публичный каталог.** Главная, страница города, карточка, служебные страницы; курс пока фиксированный.
   - Проверка: все экраны раздела 5 работают в браузере на ширине 320 px и на компьютере; лента городов показывает только города с лотами; в логах Cloudflare нет ошибок превышения процессорного времени (код 1102).
4. **Бот и мини-приложение.** Вебхук, `/start`, кнопка меню, тема Telegram, системные кнопки «Назад» и нижняя кнопка, прямые ссылки `startapp`.
   - Проверка: приложение открывается в Telegram на iOS, Android и Desktop; ссылка `?startapp=lot-1001` открывает нужную карточку; тёмная тема выглядит корректно.
5. **Админ-панель.** Проверка initData, вкладка объявлений, форма, загрузка фото в R2, справочники, журнал изменений.
   - Проверка: пользователь не из списка получает отказ 403 даже при прямом запросе к API; администратор с телефона создаёт лот с 10 фото и публикует его, и лот сразу появляется в каталоге.
6. **Заявки.** Форма, защита от спама, сообщение в группу с кнопками, вкладка заявок, выгрузка CSV.
   - Проверка: заявка приходит в группу не позже чем через 10 с; кнопка «Взять в работу» меняет статус в админ-панели; при отключённом боте заявка всё равно сохраняется и видна в админке.
7. **Подписки и рассылки.** Подписка из мини-приложения и бота, отписка, рассылка при публикации, подборка, итог в группу.
   - Проверка: после публикации нового лота подписчик получает сообщение с фото и кнопкой; повторная публикация того же лота рассылку не вызывает; заблокировавший бота пользователь помечается неактивным.
8. **Курсы, SEO, аналитика.** Ежедневная загрузка курса, мета-теги, Open Graph, schema.org, карта сайта, robots.txt, события и вкладка «Статистика».
   - Проверка: в таблице курсов появляется запись за день; `/sitemap.xml` содержит все опубликованные лоты; PageSpeed для карточки на мобильных не ниже 85; просмотр карточки отражается в статистике.
9. **Безопасность и запуск.** Turnstile, политика конфиденциальности, автоудаление старых заявок, резервные копии, Google Search Console, наполнение 10 лотов.
   - Проверка: все пункты раздела 12 выполнены; резервная копия восстанавливается в тестовую базу; оба администратора прошли полный сценарий: создать лот → получить заявку → закрыть заявку.

## 15. Как работать с этим ТЗ вместе с ИИ-ассистентом

Лучше всего работает режим «один этап — одна сессия»: ИИ получает это ТЗ целиком, сначала предлагает план этапа, вы его утверждаете, затем он пишет код и проверяет его по критериям из раздела 14.

### 15.1. Подготовка репозитория

- Экспортируйте этот документ в Markdown и положите в репозиторий как `docs/SPEC.md`.
- Создайте в корне файл с правилами для ИИ (`CLAUDE.md`, `AGENTS.md` или аналог для вашего инструмента): стек, структура папок, команды запуска и тестов, ссылка на `docs/SPEC.md`, правило «скрытые поля никогда не попадают в публичные ответы».
- Удобнее всего работать с агентом, который сам читает репозиторий, запускает команды и тесты (например, Claude Code), а не копировать код из чата.

### 15.2. Шаблон запроса на этап

```
Прочитай docs/SPEC.md. Мы делаем этап N «<название>» из раздела 14.2.
Сделанные этапы: 1–(N-1).
Сначала предложи план: какие файлы создашь или изменишь, какие
библиотеки добавишь, какие решения нужно принять мне. Код пока не пиши.
После моего «ок» реализуй этап, напиши тесты, запусти их и пройди
по пунктам «Проверка» этого этапа. В конце дай список того, что мне
нужно проверить руками.
```

### 15.3. Правила, которые экономят время

- **Секреты никогда не вставляются в чат с ИИ** и не коммитятся: только `.env.local` (в `.gitignore`) и секреты Worker в Cloudflare.
- После каждого этапа — коммит и проверка на тестовом Worker (staging), затем слияние в `main`.
- При ошибке давайте ИИ полный текст ошибки и логи Worker из панели Cloudflare или команды wrangler tail, а не пересказ.
- Если ИИ предлагает отступить от ТЗ (другую базу, библиотеку, структуру), просите объяснить причину и обновляйте `docs/SPEC.md`, чтобы документ оставался единственным источником правды.
- Отдельно просите ИИ написать тесты для двух самых опасных мест: проверки initData администратора и отсутствия скрытых полей в публичных данных.
